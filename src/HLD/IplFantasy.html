Stream Processing Layer
Apache Flink · Distributed Stream Processor
Scoring Engine
Not a microservice — a distributed stateful stream processing job. Consumes ball-events topic. Uses keyed state (player_id → [teamId, contestId] pairs) preloaded from Cassandra at match start. Fires batched ZINCRBY to Redis per ball.
RocksDB state backend 30s S3 checkpoint Exactly-once 20 workers Redis pipeline 1000 cmds/call SETNX ball dedup
Fan-out: ball event → keyed state lookup → ZINCRBY to leaderboard:{contestId} for every affected teamId · Sub-2s end-to-end at 10M users

Consumer Group · Kafka → Cassandra
Cassandra Writer Service
Separate Kafka consumer group on ball-events topic. Writes ball events and point deltas to Cassandra independently of Flink. Avoids dual-write anti-pattern — Ingestion only publishes to Kafka once; retries are isolated to Cassandra writes only.

Storage Infrastructure
Redis Cluster
In-Memory · Sorted Sets · Hashes · Strings
leaderboard:{contestId}
Sorted Set — ZINCRBY O(log N), ZREVRANK O(log N). Sharded to 10 sub-keys for mega-contest hot key prevention.
poll:{pollId}:votes
Hash — userId → chosen option. Lua script enforces atomic vote + counter update during peak 10M vote window.
poll:{pollId}:count:{opt}
String counter — live vote split %. INCR / DECR via Lua. WebSocket push after update.
poll:{pollId}:status
OPEN / CLOSED gate. SET at toss via distributed lock (SETNX poll:lock). Every vote checks this first.
session:{token}
JWT sessions with TTL for Auth Service.
milestone:{userId}:{level}
SETNX dedup for notification exactly-once dispatch at 10/30/50pt thresholds.
processed:ball:{eventId}
SETNX gate before ZINCRBY fan-out — prevents double-scoring on Flink replay.
PostgreSQL
ACID · Relational · OLTP · Strong Consistency
Tournament, Match, Player
Match metadata, squad data, lifecycle state. Low write rate, high read. Cached in Redis L2.
Poll, PollVote
Authoritative poll state. Unique constraint (user_id, poll_id). Async flush of Redis vote hash at toss via HSCAN → batch UPSERT.
Team (Fantasy)
Team metadata. SELECT FOR UPDATE for 6-team-per-user cap enforcement at deadline surge.
OutboxEvent
Outbox pattern table — written in same tx as PollVote. Debezium CDC reads and publishes to Kafka. Crash-safe event delivery.
PrizeTransaction
Financial payout records. ACID required. Idempotency key per payout. Never double-pay.
MilestoneLog
Audit trail for notification disputes. Written after FCM dispatch.
Apache Cassandra
Wide-column · Append-heavy · Time-series · Eventual
Ball_Event
Partition: match_id. Billions of append-only rows per season. Time-series pattern — ideal for Cassandra. Written by Cassandra Writer consumer group.
UserTeam
Partition: (match_id, contest_id). High write throughput during deadline rush. Up to 6 teams per user across multiple contests.
ContestEntry
Links team to contest. Same team can enter multiple contests — separate entity by design.
FantasyPoints
Partition: (match_id, contest_id). Per-ball point delta log. Append-only. Source for Flink keyed state preload at match start.
Final Leaderboard Snapshot
Written by Flink post-match. Source of truth for prize distribution Spark batch job.
AWS S3
Object Store · Durable · Cheap · Async
Flink Checkpoints
RocksDB incremental snapshots every 30s. Stores keyed state + Kafka consumer offset together. On crash: pod restarts, loads checkpoint, replays last 30s from Kafka.
Final Leaderboard Parquet

Static Assets

Caching Layers
L1 In-Process · L2 Redis · L3 CDN
L1 — Caffeine (In-Process)
Fantasy Service: squad data, player lists. Changes only at team announcement. Avoids Redis round trips for high-frequency reads.
L2 — Redis Cluster
Leaderboard sorted sets, poll split counters, session tokens, dedup keys. Sub-10ms reads. Hash-slot sharding for 10K+ parallel contests.
L3 — CloudFront CDN
Static assets, player images. Global edge cache. S3 origin. No origin hits for repeat requests.
Degraded Mode
Redis down → leaderboard reads fall back to Cassandra at 200ms vs 5ms. Poll split falls back to last PostgreSQL count. Served with degraded-mode flag.
Fault Tolerance & Guarantees
Exactly-Once Guarantees
Three Dedup Layers
1. API idempotency — Redis SETNX on request IDs for all write endpoints.
2. PostgreSQL unique constraint — (user_id, poll_id) — conflict guard for async poll flush.
3. Ball event dedup — SETNX processed:ball:{eventId} before any ZINCRBY — prevents double-scoring on Flink replay.
AZ Failure Handling
Multi-AZ All Services
K8s multi-AZ node groups. Kafka rack-aware — min 1 broker per AZ. Redis Cluster with replicas per AZ. Route53 health checks reroute in 30s. Users see brief WebSocket reconnect only.
Three Hard Invariants
Never Violated
1. No post-deadline team changes — SETNX match lock at toss, all writes rejected.
2. No duplicate votes — Redis Lua atomic + PG unique constraint as fallback.
3. No double payouts — idempotency key per payout transaction in PG with ACID.
